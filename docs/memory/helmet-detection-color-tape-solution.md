**2026-08-03 실주행 검증 완료.** 사람 발견→정지→5초 판단→착용 확인 시 재개 사이클이 실제로 동작함. 이 값들 바뀌면 재현 안 되니 재보정 시 반드시 이 기록부터 볼 것.

## 8가지 실패 — 순서대로, 각각 실측값과 함께

흰 안전모라서 겪은 문제다. 색이 있는 안전모라면 처음부터 3번 필요 없이 바로 됐을 것.

1. **흰 안전모 색(HSV) 매칭** — 착용 0.037~0.069 / 미착용 0.030~0.048, 안 갈림. 잡힌 게 안전모가 아니라 흰 천장이었음(덩어리 높이 144~155px로 양쪽 동일)
2. **Haar 얼굴 검출 후 그 위를 봄** — 바닥에서 올려다보는 각도라 6장 중 1장만 검출, 맞아도 눈 주변 55px(실제 얼굴 200px)만 잡음
3. **사람 상자 맨 위 얇은 띠의 머리카락(hair 방식)** — 정지 상태에서는 착용 0.000(18/18) / 미착용 0.064~0.094 로 갈렸으나
4. **같은 방식을 순찰 거리에서** — 상자 top 이 실제 머리보다 20px 위로 잡혀 0/3 검출 실패
5. **띠를 아래로 오프셋** — 미착용 39/41 잡히지만 착용도 12/18 오탐(안전모 챙 그림자에 걸림)
6. **위에서 첫 어두운 덩어리 높이** — 착용도 0.16까지 나와 분리 안 됨
7. **피부색으로 얼굴 찾아 그 위** — 착용 0~0.535 / 미착용 0~0.687, 완전히 겹침
8. **주변 대비 상대 어두움/두께** — 착용이 오히려 더 두꺼움(0.096~0.287 vs 0.013~0.216), 원리상 착용시 챙+눈, 미착용시 머리카락+눈이 둘 다 "두꺼운 어두운 구간"을 만들어 구분 안 됨

**공통 원인:** 흰 안전모가 흰 벽·천장과 같은 색이라 "머리가 어디서 시작하는지" 자체를 못 찾음. 게다가 웹캠에 노출 제어가 없어(`brightness`만 있음) 형광등 아래서 자동노출이 화면을 올리면 머리카락이 V 43~100 → V 115~157 로 벽과 같아짐 — 조명 문제까지 겹쳤다.

## 최종 해법 — 초록 테이프, 위쪽 돔에

사용자 제안("안전모 위에 뭐가 덮여 있으면 착용으로 본다")에서 출발. 안전모 **앞면 위쪽(돔)**에 초록 테이프 2줄 부착. `method:=color`.

**⚠️ 붙이는 위치가 성패를 갈랐다:**
- **아래쪽에 붙였을 때 실패** — 바닥 카메라가 올려다보는 구도라 안전모 자신의 돔 그늘에 들어가 채도가 반토막(S 66~205→35~60), 색상도 밀림(H 75~83→80~120). 벽·옷과 안 갈림
- **위쪽 돔으로 옮기니 성공** — 천장 조명을 직접 받아 H 75~83, S 64~109 로 선명. 이 방의 다른 모든 표면은 H 12~22 라 겹칠 게 없음

**실측 기준값 (2026-08-03, 같은 자리·조명에서 8장씩):**
- 착용: 초록 비율 0.0199~0.0289
- 미착용: 0.0000 (8장 전부 정확히 0)
- `helmet_ratio: 0.010` (양쪽 2배 이상 여유)
- `head_width: 0.35` (테이프처럼 작은 표식은 머리 영역을 좁혀야 비율이 살아남 — 넓으면 벽에 희석)

## 판정 흐름 — 왜 "정지 후 5초간 모아서" 인가

사람 검출(MobileNet-SSD)은 확신도 0.86~1.00으로 안정적인데, 안전모 판정은 로봇이 움직이면 흔들린다(모션블러·거리변화·상자어긋남). 그래서:

```
사람 2프레임 연속           → 순찰 정지 (안전모 여부와 무관하게 먼저 세움)
5초 동안 판정을 모은다      → 미착용이 "사람 프레임 수의 50% 이상"이면 확정 (개수 아님!)
   미착용 확정 → 부저 3번(ERROR) 3연타, 5초마다 반복, 판단창 재시작
   착용 확정   → 부저 1번(ON) 1회, 순찰 재개
```

**개수 기준이면 안 되는 이유(실주행에서 실제로 틀렸음):** 안전모를 쓰고 있었는데 14장 중 4장이 미착용으로 나와(머리가 화면에서 잘린 프레임) 개수 기준 "2장 이상"에 걸려 오판. 진짜 미착용은 항상 100%(14/14, 16/16, 11/11)였으므로 **비율 기준(`judge_bad_min=3`, `judge_bad_ratio=0.5`)** 으로 바꿔서 해결.

**통과한 사람을 다시 세우지 않는 잠금(`ok_cleared`)이 있는데, 사람이 한 프레임만 안 보여도 풀리면 안 됨** — 검출이 40~90%로 끊기다 보니 계속 리셋되어 30초간 4번 정지·출발을 반복한 적 있음. `absent_streak >= clear_frames`(약 7초) 이상 안 보여야 풀리게 고침.

**즉시 재정지 조건(`alert_frames`)은 5/6로 거의 만장일치 요구** — 3/6이면 머리가 잠깐 화면 밖으로 나가도 세움.

## 부수적으로 바뀐 것

- Nav2 순찰 속도 `max_vel_x` 0.15→**0.10 m/s** — 느리게 가면 모션블러·흔들림이 줄어 판정이 쉬워짐
- `helmet_node`에 `nice +10`, `cv2.setNumThreads(1)` 추가 — VM 2코어에서 추론이 Nav2 컨트롤러 CPU 를 뺏어 순찰 한 구간이 16초→107초가 된 적 있어 양보시킴
- `patrol_node`에 `vision_wait_sec`(기본 40초) 추가 — 시작지점 도착 후 `/helmet/ready` 를 기다렸다 출발. DDS 디스커버리가 16~40초 걸려서 그 전에 출발하면 첫 구간을 눈 감고 돎
- 웹캠(`webcam_node.py`)은 **부팅당 한 번만 열고 계속 유지** — 여러 번 열고 닫으면 장치가 잠겨(`select() timeout`) 로봇 재부팅해야 풀리는 사고를 겪음. `SIGTERM` 핸들러 추가, `/webcam/enable=False` 여도 장치는 안 놓고 발행만 멈춤

## 알려진 한계

- 흰/무채색 안전모나 테이프 없이는 이 방법 자체가 안 됨 (색이 있는 안전모라면 테이프 불필요)
- 프레임당 검출률이 낮음(사람 상자 top이 머리와 20px 어긋나는 경우가 흔함) — 그래서 판단창을 5초/여러 장으로 모으는 구조가 필수. 한 장 판정으로 바꾸면 다시 깨짐

웹캠 각도를 다시 잡은 뒤(상향 35~40°, 좁은 방이라 근거리 커버에 이 각도가 맞음) 위 2026-08-03 기준이 깨져 재등록했다.

- **증상:** 착용인데 초록 비율 0.003~0.006(문턱 0.010 미달) → 미착용 오판. 테이프 화소의 V가 90~114 대역으로 어두워져 등록 하한(V≥114)에 잘림
- **함정(재발 주의):** 재등록 ROI를 **테이프 화소의 경계 사각형(bbox)으로 잡으면 안 된다** — 모서리의 흰 헬멧 화소(저채도라 H 불안정)가 섞여 H 하한이 30까지 내려갔고, 머리카락(H 35~42, S ~30, V ~70)이 범위에 들어와 **미착용자가 착용으로 통과**했다. ROI는 테이프 **안쪽 순수 영역만**(순도 100% 확인 후) 잡을 것
- **최종 기준:** H 61~84, S 51~173, V 59~203 (`helmet_calib.yaml`, 근거 사진 `logs/helmet_calib/on0814_recalib.jpg`, 이전 기준 백업 `.bak_20260814`)
- **실측(1.5m, 5장씩):** 착용 0.047~0.051 / 미착용 0.0000~0.0014 — 문턱 0.010 기준 양쪽 5배·7배 여유, 배경 매칭 0%
- 머리카락과의 분리는 **H 축**이 담당한다(테이프 H 66~78 vs 머리카락 35~42). V는 조명 따라 움직이니 V 하한에 기대지 말 것
