로봇(ros18, Pi 3)에서 `vcgencmd get_throttled`가 **`0x50000`**을 반환한다: `0x10000`(저전압 발생 이력) + `0x40000`(쓰로틀링 발생 이력). 2026-07-28 확인 시 하위 비트는 0이라 **당시 진행 중은 아니었다**.

**Why:** Pi 3는 순간 전류 소모가 크고, TurtleBot3 배터리가 약해지면 전압이 떨어져 CPU가 강제 감속된다. 방치하면 SD카드 손상이나 예고 없는 재부팅으로 이어질 수 있다. 성능 이상(프레임 저하 등)을 디버깅할 때 소프트웨어만 의심하면 원인을 놓친다.

**How to apply:** 순찰 자동화처럼 장시간 돌리는 테스트 전에 배터리 충전 상태를 확인한다. 성능이 갑자기 나빠지면 `vcgencmd get_throttled`의 **하위 비트**(`0x1` 저전압 진행중, `0x4` 쓰로틀링 진행중)를 먼저 본다. 온도는 정상이었다(60.1°C).

참고: `vcgencmd get_camera`가 `supported=0 detected=0`으로 나오는 것은 libcamera 스택에서 신뢰할 수 없는 레거시 체크이므로 무시한다. 카메라 인식 판단은 `cam -l`로 한다.

## Pi 4 로 바꾼 뒤 — 저전압 이력은 사라졌지만 소모는 늘었다 (2026-08-07)

**좋아진 것:** 새 SD 클린 설치 후 `vcgencmd get_throttled` 가 하루 종일 **`0x0`** 이었다(설치·주행·순찰 전부). 위의 `0x50000` 이력은 Pi 3 시절 것이고, Pi 4 + 어댑터/충전기 조합에서는 재현되지 않았다. 온도도 최고 59°C 로 여유 있다(쓰로틀 시작은 80°C).

**나빠진 것 — 배터리 소모:** Pi 4 는 Pi 3 보다 전력을 더 먹고(유휴 약 2.7W vs 1.9W, 부하 6~7W vs 4W), 거기에 **Nav2 를 온보드로 옮겨 CPU 20~25% 를 상시 쓴다**(예전 Pi 3 는 센서 중계만 해서 약 12%). 결과적으로 **한 번 충전으로 도는 시간이 짧아졌다.** "VM 은 화면만" 구조의 대가다.

사용자가 "Pi 4 로 바꾸니 충전이 느려진 것 같다"고 했는데, **충전 속도 자체는 변하지 않았다**(배터리를 빼서 별도 충전기로 충전하므로 로봇과 무관). 더 깊이 비우니 채우는 데 오래 걸리고 더 자주 충전하게 되는 것이다.

**How to apply:**
1. **정지 작업은 어댑터로 한다** — ROS 설치, 파라미터 확인, 카메라·라이다 진단, 코드 작업은 바퀴가 돌 필요가 없다. 2026-08-07 에 하루 작업의 대부분이 여기 해당했고, 어댑터로 돌린 구간에서는 12.13V 가 유지됐다. 배터리는 주행 시험에만 쓴다
2. **배터리를 하나 더 사는 것을 권한다** — 이 문제의 표준 해법이다(하나 충전 / 하나 주행). 시연·대회에서는 사실상 필수
3. **11.3V 에서 멈춘다** — 3셀이므로 11.0V 는 셀당 3.67V 로 안전 하한이다. 2026-08-07 에 11.17~11.21V 까지 여러 번 갔는데(셀당 3.72V) 경계선이다. 자주 반복하면 수명이 준다
